# fastgpt-sync-adapter 需求分析

> 依据：《多源数据归集与智能体项目需求文档 V1.1（草稿，待评审）》（2026-10-10）第三、四、五章，
> 及 FastGPT 官方文档《API 文件库》（https://doc.fastgpt.io/zh-CN/guide/dataset/third-party/api_dataset）。
> 项目目录当前为空仓库，本分析用于界定本服务的需求边界与接口契约。

---

## 1. 本服务在整体项目中的定位

整体项目链路：

```
飞书 ──┐
       ├─► (单向同步) ──► NAS ──► (FAST 平台向量化/打标签) ──► FastGPT 知识库 ──► 6 个智能体
企业微信 ┘                ▲
                          └── 业务人员手工上传 Office 文件（Word/Excel/PPT/PDF）
```

**fastgpt-sync-adapter 的职责边界（本次明确）：**

- 把**飞书**、**企业微信**的文件同步至 NAS（**单向同步**，只写 NAS，不回写源平台）。
- **不更改文件的任何内容**（原样落盘，与需求文档 F-01/F-02 一致）。
- 其他需求（权限、增量、存储、解析等）按文档第三、四、五章执行。

NAS 上的存量文件与同步落盘的文件，后续通过 **FastGPT API 文件库** 规范暴露给 FastGPT，由 FastGPT 侧完成向量化与检索（对应需求文档中 "FAST 平台" 角色）。本服务天然适合同时承担 "API 文件库适配层" 的角色：同步器把数据放进 NAS，适配器把 NAS 目录按 FastGPT 规范暴露为 `/v1/file/*` 接口。

## 2. 总体约束（来自第二章，对本服务是硬性要求）

| 编号 | 约束 | 对本服务的含义 |
|---|---|---|
| N-04 | 所有跨平台数据仅做单向同步，禁止反向写回 | 服务只调用源平台的**读取**接口，只写 NAS；不得调用任何源平台的写/删/改接口 |
| 关键约束 | 归集至 NAS 的数据保持原始形态，加工结果不回写覆盖原始数据 | 落盘字节流与源端完全一致；任何解析、清洗、向量化产物必须写到**独立目录/库**，不得覆盖原始文件 |
| — | NAS 双重角色：既是归集落盘位置，也是人工上传 Office 文件的来源端 | 目录规划需区分「同步区」（企微/飞书落盘）与「人工上传区」，两类数据统一由 FAST 处理 |

## 3. 第三章：NAS 数据接入需求（人工上传文件）——对本服务的要求

本章描述的是 NAS 侧**存量/人工上传**文件的接入规则。虽然"人工上传"本身不由本服务执行，但本服务需保证同步落盘的数据**与人工上传文件遵守同一套后续处理约定**，以便 FAST/FastGPT 统一处理。

### 3.1 目录扫描与增量识别

- **NA-02 目录扫描**：按约定目录范围自动扫描，识别新增、变更与删除的文件，无需人工提交清单。
  - 本服务需提供/约定同步落盘的**目录结构规范**（待明确事项 Q-02），使 NAS 扫描器能覆盖同步区。
- **增量与去重**：
  - 按「文件最后修改时间 + 内容哈希」识别增量，仅处理新增、变更文件。
  - 全量重扫以「**路径 + 哈希**」作为唯一标识去重。
  - 对本服务的含义：落盘时应**保留源端的 mtime**（或写入元数据），并保证同一路径下同名文件被**原地覆盖更新**（而非产生副本），否则会造成重复向量化。

### 3.2 元数据保留（溯源要求）

需保留的元数据：**文件名、存储路径、上传人、上传时间、最后修改时间**。

对本服务的含义：同步器在 NAS 落盘时，除文件本体（原样）外，建议**附带一份元数据记录**（如 sidecar `.meta.json` 或统一的元数据索引库），记录源平台、源端文件 ID、上传人/作者、源端创建/修改时间、拉取时间、内容哈希。注意：

- 元数据文件属于"加工产物"，**必须与原始文件分目录存放或明确命名隔离**，避免污染"原始数据不动"的红线。
- 若选择不改目录、只用文件系统 mtime，则上传人等源端信息会丢失，不利于权限归属与溯源——建议保留 sidecar 方案，并在与甲方评审时确认。

### 3.3 权限归属与隔离（与第四、五章联动）

- 手工上传文件按"指定文件夹"赋权限，非所有人员可访问。
- 权限隔离规则与企微、飞书数据保持一致：不同角色仅能检索授权范围内的文件。
- **部门经理**可检索本部门所有员工权限范围内的文件及群聊记录；**总裁**可检索全公司范围。

对本服务的含义：本服务落盘的目录结构需要能承载权限语义。可行做法：

- 同步区按 `来源平台/数据类型/归属主体（部门/群/空间）/` 分层，权限元数据随 sidecar 或索引库记录"可见主体列表"（群成员、文档协作者、目录授权角色）。
- 真正的权限**判定与过滤**发生在 FastGPT 检索层（结合 FastGPT 知识库文件级权限/标签），本服务负责提供足够准确的归属元数据。

### 3.4 解析要求的归属划分

第三章的 Word/PPT/Excel/PDF 解析要求（按标题层级提取、Excel 转"表头+行记录"、PDF 按需 OCR）属于 **FAST 平台/FastGPT 侧**职责，**不属于**本服务。本服务坚持"不更改文件任何内容"，只保证原文件可被下游读取。

## 4. 第四章：企业微信数据同步需求

### 4.1 接口选型

- 使用**企业微信官方会话存档接口**作为数据拉取通道。
  - 即「企业微信会话内容存档」（msg_audit）SDK：通过 `get_chat_data` 拉取加密消息，`decrypt_data` 解密，`get_media_data` 拉取图片/文件/语音等媒体附件。
  - 前提：客户已采购会话存档点位并配置授权（待明确事项 Q-01：点位数量与采购分配方案）。

### 4.2 数据形态与落盘

- **拉取的原始 JSON 数据保存在 NAS 中**（文档明确原始 JSON 落盘）。
  - 落盘建议：按 `企微/会话存档/{年份月份}/{群或会话标识}/{seq 或 msgid}.json` 组织；媒体附件按消息关联存储（原样字节，不解码不转码）。
  - 本服务"不更改文件内容"在此体现为：解密后的**原始消息 JSON 原样写入**、媒体文件**原样字节写入**；不做格式转换、不做合并。

### 4.3 权限规则（W-01）

- 会话权限按群组人员对应：群成员可检索该群聊天内容；**被移出群组后仅保留移出前历史记录的权限**，后续更新内容对其不可见。
- 对本服务的含义：同步器需维护「群成员快照 + 变更事件」记录（企微会话存档可拉取群成员变更类消息/或定期同步通讯录），sidecar 元数据中记录每条/每段消息的"可见成员集合的有效期"，供检索层按用户当前/历史身份过滤。

### 4.4 更新规则

- 用户被移出群聊后，不再同步更新**该用户视角**的后续内容。
  - 注意文档表述：存档接口拉取的是群的消息流（与用户视角无关），此条实际约束的是**检索可见性**而非同步行为——同步器继续拉群消息，检索层对已被移出者隐藏移出后的内容。

### 4.5 网络访问

- 客户侧已配置公网 IP 与深信服穿透规则；供应商可通过穿透账号完成接口连通性验证，无需本地驻场。
  - 对本服务的含义：部署位置需与甲方确认（待明确事项 Q-05：FAST 平台私有化或托管）。若服务部署在供应商侧，经穿透访问客户 NAS 与企微接口；若私有化部署在客户侧，则直连。连接串、凭证通过配置注入。

## 5. 第五章：飞书数据同步需求

### 5.1 数据源覆盖范围

- 通过**飞书官方集成平台（AnyCross）/开放平台 API** 拉取全量数据，包含但不限于：**云文档、邮件、会议纪要、多维表**等所有可访问内容，无需部门负责人手动筛选导入。
- **备注：飞书群聊聊天记录本次不列入同步范围。**

对本服务的含义——需覆盖的拉取对象：

| 数据类型 | 飞书侧接口（开放平台） | 落盘形态 |
|---|---|---|
| 云文档（docx/sheet/bitable 等） | Docs API：`/open-apis/docx/v1/documents/{id}/raw_content`、导出接口 | 文档导出为原始格式（如 docx/pdf）或原始内容 JSON，**原样保存** |
| 邮件 | Mail API（需开通邮件 API 权限，边界见 Q-03：全员 or 授权范围） | eml/原始 JSON |
| 会议纪要 | 妙记/会议 Minutes API | 原始记录（文本/JSON/音视频附件原样） |
| 多维表 | Bitable API | 记录 JSON（原样） |
| 云空间文件 | Drive API：`/open-apis/drive/v1/files`、`/download` | **原文件字节流直接落盘，不转码** |

### 5.2 存储规则（F-01 / F-02）——本服务核心红线

- **F-01 原样同步**：所有拉取内容原汁原味同步至 NAS，与飞书侧原始内容完全一致。
- **F-02 禁止二次加工**：禁止在 NAS 侧做版本合并、二次加工，避免数据溯源困难。

对本服务的硬性要求：

- 落盘内容 = 源端字节/原文，**不做**去重合并、格式转换、内容清洗、压缩重写。
- 云文档若通过导出接口获取，需固定一种导出格式并在元数据中记录导出方式与源文档 ID/版本；同一文档更新后**生成新版本文件而非原地改写历史版本**（或原地覆盖但保留源端版本号元数据——二选一，需评审确认；推荐保留版本历史以满足"溯源"）。

### 5.3 增量更新规则

- **定时轮询**机制拉取增量；轮询时间与频率**可配置**，默认**每日凌晨非业务高峰**执行，避免占用带宽。

对本服务的要求：

- 调度器：cron/可配置间隔（如 `FEISHU_SYNC_CRON=0 2 * * *`）。
- 增量判据：飞书侧 `edit_time`/文档版本号 + 本地已同步游标（记录每对象 last_synced_version），仅拉取变更对象。
- 断点续跑与失败重试：单对象失败不阻塞整轮，记录失败清单供补偿。

### 5.4 权限归属逻辑

- 按飞书文档的**协作者**作为文件的权限划分依据。
- 用户被移出协作者列表后，同步取消该文件权限。

对本服务的含义：每次同步时同时拉取文档的协作者/权限成员列表（Permission API），写入该文件的元数据（可见用户 open_id 列表 + 更新时间）；检索层以此过滤。协作者变更 → 下一轮同步时元数据随之更新。

## 6. FastGPT API 文件库对接（本服务的出口契约）

FastGPT 通过「API 文件库」对接外部文档库：创建知识库时选择 API 文件库类型，配置三个参数：

- `baseURL`：本服务的文件服务接口地址
- `authorization`：鉴权 token（FastGPT 以 `Authorization: Bearer <token>` 调用）
- `basePath`：可选，文件树根目录（用于指定起始位置）

本服务需实现以下 4 个接口（统一响应格式 `{success: boolean, message: string, data: any}`）：

### 6.1 `POST /v1/file/list` — 获取文件树

- 入参：`parentId`（可选，null 时用 basePath 作根）、`searchKey`（可选检索词）。
- 返回 `FileListItem[]`：`{id, parentId, name, type: 'file'|'folder', updateTime, createTime, hasChild?}`。
- 实现要点：把 NAS 同步区 + 人工上传区的目录树映射为该结构；`id` 建议采用稳定的哈希（路径哈希或源端文件 ID），保证增量同步后 FastGPT 侧能识别同一文件。

### 6.2 `GET /v1/file/content?id=xx` — 获取文件内容

- 返回 `{title?, content?, previewUrl?}`，**content 与 previewUrl 至少返回一个**，同时返回时 content 优先。
- 对本服务的关键决策（与"不更改文件内容"红线对齐）：
  - **推荐返回 `previewUrl`**：指向 NAS 上原始文件的临时可下载链接（本服务签发短时效 URL 或内网地址），由 FastGPT 访问该 URL 自行下载解析（支持 PDF/Word/Markdown 等格式），解析结果由 FastGPT 缓存。这样本服务完全不做内容加工。
  - `content`（直接返回提取后文本）仅在不方便提供可访问 URL 时使用；若用 content，文本提取也属于加工，需谨慎界定——建议统一走 previewUrl。

### 6.3 `GET /v1/file/read?id=xx` — 获取原文阅读链接

- 返回 `{url}`，用户点击后打开原文。实现为指向 NAS 原文的可访问链接（或本服务的下载端点）。

### 6.4 `GET /v1/file/detail?id=xx` — 获取文件详情

- 返回 `{id, name, parentId, type, updateTime, createTime}`，直接映射 sidecar/索引库中的元数据。

### 6.5 权限衔接说明

FastGPT 侧另有「知识库文件级权限/集合标签」能力。本服务的职责是：通过 list/detail 的稳定 ID 与元数据，支撑在 FastGPT 侧按"目录=权限域"或标签体系配置可见性，实现第三章的角色隔离（部门经理/总裁视图）与 W-01、飞书协作者规则。权限的最终判定建议在检索层落地，本服务保证元数据真实、及时。

## 7. 本服务需求汇总（功能清单）

1. **飞书同步器**：拉取云文档、邮件、会议纪要、多维表等全量可访问内容（**不含群聊**），原样落盘 NAS；定时轮询（可配置，默认每日凌晨）；按协作者记录权限元数据。
2. **企微同步器**：通过会话存档接口拉取群聊/单聊原始 JSON + 媒体附件，原样落盘 NAS；维护群成员变更快照支撑 W-01。
3. **单向与不改内容红线**：仅调用源平台读接口；落盘字节与源端一致；加工产物（元数据、索引）与原始数据隔离存放。
4. **增量与去重配合**：按源端版本/修改时间 + 内容哈希增量；同路径原地更新或版本化（评审确认）；保留源端 mtime。
5. **元数据管理**：sidecar `.meta.json` 或索引库记录文件名、路径、上传人/作者、源端时间、哈希、可见主体。
6. **FastGPT API 文件库适配层**：实现 `/v1/file/list`、`/v1/file/content`（优先 previewUrl）、`/v1/file/read`、`/v1/file/detail` 四接口 + Bearer 鉴权 + basePath 支持。
7. **部署与网络**：支持客户私有化部署（直连 NAS + 经穿透/公网访问企微、飞书 API），凭证与目录规范配置化。

## 8. 待评审确认事项（映射文档第八章）

|---|---|---|
| Q-01 | 企微会话存档点位数量与采购分配 | 决定可同步的会话范围 |
| Q-02 | NAS 目录结构与命名规范 | 决定同步落盘布局与权限域划分 |

| Q-04 | 数据保留与清理策略 | 决定本服务是否需要清理/归档逻辑 |
| Q-05 | FAST 平台部署位置 | 决定本服务部署形态与网络拓扑 |
| Q-09 | NAS 人工上传扫描范围与频率 | 决定适配层是否需要主动扫描人工上传区 |
| Q-10 | 扫描件/图片型 PDF 是否 OCR | 若需 OCR，属于 FAST 侧加工，不在本服务 |
| Q-11 | Office 文件密级/归属人是否人工补录 | 决定权限元数据来源（目录约定 or 人工登记） |
