## 已确认的需求（2026-10-29）

1. **权限边界**：只给名单内的在职员工建目录、落副本。**以名单为准**：授权了飞书但不在名单内的人，不拉取。
   - **员工 ID 用企微 `user_id`**：名单（飞书多维表格）以企微 `user_id` 为键，查出对应的飞书身份。文件服务 token、数据库归属都用这个 ID（目录名不带 ID，见第 6 条）；没有企微账号的员工用 `feishu:<open_id>`（A16）。
   - **纳管员工** = 在名单内 + 状态在职 + 姓名非空 + 与其他在职员工不重名。只有纳管员工才建目录、落副本、发 token。
2. **飞书应用**：统一成一个同步应用，可行性待实测。
3. **FastGPT 对接方式**：从"主动推送"改为由 FastGPT 的 **API 文件库从 adapter 拉取**。文件始终存在 NAS 上，adapter **不再创建或管理 FastGPT 知识库**，知识库的创建和配置由 FastGPT 侧负责。
4. **adapter 的边界**：把数据按人整理到 NAS，并通过 API 文件库接口按员工隔离提供文件；FastGPT 侧的知识库、工作流和飞书机器人不在 adapter 范围内。
   - 权限隔离只靠"每人一份副本 + 每人专属 token"，**不使用 FastGPT 标签**，adapter 不给文件打标签（2026-10-29 确认）。
5. **拉取范围**：
   - **企微**：名单内员工的会话，从头全量拉取。
   - **飞书**：**谁授权就拉谁**。员工完成飞书 OAuth 授权后，用他本人的身份拉取，只同步当前状态；没授权的人不拉。每个授权人拉三类：
     - 云盘："我的文件夹"和"共享文件夹"下，归我所有以及与我共享的全部文档；
     - 智能纪要：归我所有、我参与的、与我共享；
     - 邮件：收到的和已发送的邮件，正文 + 附件。
6. **离职**：员工目录原地改名为 `<人名>_离职`，停止同步，吊销 token，旧数据永久保留。
   - **NAS 目录名就是人名**：根目录下直接是员工目录，不带 ID，不分 `在职/` `离职/`（2026-10-29 确认）。
7. **权限变化**：失去权限后直接删除该人目录里的文件，不留档；文档移动或改名后，FastGPT 重新索引。
8. **愿景**：FastGPT、企微、飞书三方权限统一，并做到近乎实时。v2 采用"事件驱动 + 对账"，目标是常见变更在 1～2 分钟内对齐。
